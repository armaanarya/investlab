### Task 1: `money.py`

**Files:**
- Create: `src/investlab/money.py`
- Test: `tests/test_money.py`

**Interfaces:**
- Consumes: nothing.
- Produces: `Money = Decimal`; `ZERO: Money`; `CENT: Decimal`; `usd(value: int | str | Decimal) -> Money`; `usd_ceil(value: int | str | Decimal) -> Money`; `round_shares(value: int | str | Decimal) -> int`.

**Design notes for the implementer:**
- `usd` quantizes to `Decimal("0.01")` with `ROUND_HALF_UP`. It **rejects `float` with `TypeError`** — accepting a float and silently quantizing is how float creeps into a money system. `bool` is rejected too (it is an `int` subclass).
- `usd_ceil` quantizes with `ROUND_CEILING`. It exists for one purpose: estimating a cost or fee conservatively, so a rounding error can never make an order look affordable when it is not.
- `round_shares` uses `ROUND_FLOOR`, not `ROUND_DOWN`. Floor, so a negative quantity rounds away from zero rather than toward it — "never rounds up" means the value never increases, at any sign. Rounding shares up silently breaks every cash and risk constraint.

```python
"""Decimal money and share-count arithmetic.

Float is never used for money anywhere in this project. Every boundary
quantizes to cents. Share counts are integers and are never rounded up.
"""

from __future__ import annotations

from decimal import ROUND_CEILING, ROUND_FLOOR, ROUND_HALF_UP, Decimal

Money = Decimal

CENT = Decimal("0.01")
ZERO = Decimal("0.00")


def _coerce(value: int | str | Decimal) -> Decimal:
    if isinstance(value, bool) or isinstance(value, float):
        raise TypeError(f"money must never come from {type(value).__name__}; use Decimal or str")
    if isinstance(value, Decimal):
        return value
    if isinstance(value, (int, str)):
        return Decimal(value)
    raise TypeError(f"cannot build money from {type(value).__name__}")


def usd(value: int | str | Decimal) -> Money:
    """Quantize to cents, ROUND_HALF_UP. The default money constructor."""
    return _coerce(value).quantize(CENT, rounding=ROUND_HALF_UP)


def usd_ceil(value: int | str | Decimal) -> Money:
    """Quantize to cents, always upward. For costs and fees only."""
    return _coerce(value).quantize(CENT, rounding=ROUND_CEILING)


def round_shares(value: int | str | Decimal) -> int:
    """Round a share count DOWN, at any sign. Never up, ever."""
    return int(_coerce(value).to_integral_value(rounding=ROUND_FLOOR))
```

### Task 2: `ledger.py` — fills, FIFO sells, snapshot

**Files:**
- Create: `src/investlab/portfolio/ledger.py`
- Test: `tests/portfolio/test_ledger.py`

**Interfaces:**
- Consumes: `investlab.money.{usd, usd_ceil, round_shares, Money, ZERO}`; `investlab.contracts.{AccountState, Action, AssetClass, Fill, Lot, Position}`.
- Produces:
  - `class LedgerError(Exception)`, `InsufficientCashError(LedgerError)`, `InsufficientSharesError(LedgerError)`, `DuplicateDividendError(LedgerError)`, `UnknownSymbolError(LedgerError)`
  - `@dataclass(frozen=True) RealizedTrade(symbol, quantity, opened, closed, proceeds, cost_basis, realized_pnl)`
  - `class Ledger(cash: Decimal, *, allow_margin: bool = False)` with properties `cash`, `positions: tuple[Position, ...]`, `receivables`, `liabilities`, `fills: tuple[Fill, ...]`, `realized: tuple[RealizedTrade, ...]`, `realized_pnl: Decimal`
  - `Ledger.apply_fill(fill: Fill, asset_class: AssetClass = AssetClass.STOCK) -> None`
  - `Ledger.snapshot(marks: Mapping[str, Decimal], as_of: date) -> AccountState`

**Design notes:**
- Sell direction is `Action.SELL`, `Action.REDUCE`, `Action.EXIT`. Buy is `Action.BUY`. `HOLD`, `REVIEW`, `NO_TRADE` raise `ValueError` — they are plan verbs, not transactions.
- Buy: `cash -= usd(qty*price) + commission + fees`. With `allow_margin=False`, a buy that would drive cash below zero raises `InsufficientCashError` and leaves the ledger untouched.
- Sell: FIFO by `(lot.opened, insertion order)`. Partial consumption of a lot rebuilds it with the remaining quantity **and a proportionally reduced commission** (`remaining = lot.commission - usd(lot.commission * consumed / lot.quantity)`), so `Lot.gross_cost` stays meaningful and entry commission is amortized rather than double-counted.
- `realized_pnl` per consumed slice = `proceeds_net_of_exit_costs - (basis + entry_commission_consumed)`. Exit commission and fees are apportioned across the consumed lots pro rata by quantity, with the residual on the last slice so the sum is exact.
- Positions with quantity 0 are dropped, so `snapshot` never demands a mark for something no longer held.
- `snapshot` validates that `marks` covers every held symbol and raises `UnknownSymbolError` naming the symbol. Marks are passed through `usd`. The returned `AccountState` gets a **copy** of the marks dict, not the caller's.
- Quantity must be > 0 on every fill; price, commission, fees must be >= 0.

### Task 3: `ledger.py` — splits and dividends

**Files:**
- Modify: `src/investlab/portfolio/ledger.py`
- Test: `tests/portfolio/test_ledger.py` (append)

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) DividendAccrual(symbol, per_share, ex_date, pay_date, shares, amount, paid: bool)`
  - `@dataclass(frozen=True) SplitRecord(symbol, ratio, effective, cash_in_lieu)`
  - `Ledger.apply_split(symbol: str, ratio: Decimal, effective: date) -> SplitRecord`
  - `Ledger.apply_dividend(symbol, per_share: Decimal, ex_date: date, pay_date: date) -> DividendAccrual`
  - `Ledger.settle_dividends(as_of: date) -> tuple[DividendAccrual, ...]`
  - `Ledger.dividends: tuple[DividendAccrual, ...]`

**Design notes:**
- **Split.** `ratio` is new-shares-per-old-share: 2-for-1 is `Decimal("2")`, a 1-for-10 reverse is `Decimal("0.1")`. Per lot: `new_qty = round_shares(qty * ratio)`; new per-share basis = `(qty * price) / new_qty` quantized to 8 dp (sub-cent basis precision, documented — cents would lose value on a 3-for-1). Any fractional share left over becomes **cash in lieu at basis**, which moves value from shares to cash without creating P&L. Total economic value (position basis + cash in lieu) is preserved.
- Splitting a symbol with no position raises `UnknownSymbolError`. `ratio <= 0` raises `ValueError`.
- **Dividend.** `apply_dividend` recognizes a receivable on the ex-date: `amount = usd(per_share * shares_held_at_ex_date)`, and `receivables += amount`. It does **not** touch cash. A second call with the same `(symbol, ex_date, pay_date)` raises `DuplicateDividendError` — credited exactly once, always.
- `settle_dividends(as_of)` converts every unpaid accrual with `pay_date <= as_of` into cash and marks it paid. Settlement moves value between two equity terms, so **equity is identical before and after**. That is the whole point: payment timing never creates fake P&L.
- Settlement is never implicit. `snapshot` does not settle — it reports whatever state exists, and the identity holds either way.

### Task 4: `ledger.py` — reconciliation against the platform statement

**Files:**
- Modify: `src/investlab/portfolio/ledger.py`
- Test: `tests/portfolio/test_ledger.py` (append)

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) FillDiscrepancy(ours: Fill, theirs: Fill, fields: tuple[str, ...])`
  - `@dataclass(frozen=True) Reconciliation(matched, only_in_ledger, only_in_statement, discrepancies)` with `in_agreement: bool` and `summary() -> str`
  - `Ledger.reconcile(statement_fills: Sequence[Fill]) -> Reconciliation`

**Design notes:**
- The platform is the authoritative record; this is our reconciled copy. `reconcile` is **read-only**: it never edits our fills to match. Differences stay visible until a human resolves them.
- Matching, in order: (1) exact identity on `(symbol, session, action, quantity, price, commission, fees)` as a multiset — equal fills pair off; (2) leftovers pair on `(symbol, session, action)` and report which fields differ; (3) whatever is still unpaired lands in `only_in_ledger` (we recorded a trade the platform did not) or `only_in_statement` (the platform filled something we never recorded).
- `summary()` returns counts only. No prose.

### Task 6: `sizing.py` — the integer share solver

**Files:**
- Create: `src/investlab/portfolio/sizing.py`
- Test: `tests/portfolio/test_sizing.py`

**Interfaces:**
- Consumes: `investlab.money.{usd, usd_ceil, round_shares, ZERO}`; `investlab.contracts.{Action, BlockReason, BlockedOrder, SizedOrder, SizingConstraints}`.
- Produces:
  - `class BindingConstraint(str, Enum)` with `RISK_BUDGET = "risk_budget"`, `SPENDABLE_CASH = "spendable_cash"`, `POSITION_CEILING = "position_ceiling"`
  - `GAP_STRESS_FRACTION = Decimal("0.20")`
  - `def planned_loss(quantity, price_bound, protective_reference, constraints) -> Decimal`
  - `def size_order(symbol, price_bound, protective_reference, constraints, *, current_position_value=Decimal("0"), rationale="") -> SizedOrder | BlockedOrder`
  - `@dataclass(frozen=True) Candidate(symbol, price_bound, protective_reference, rank=0, current_position_value=Decimal("0"), rationale="")`
  - `def size_batch(candidates, constraints) -> tuple[SizedOrder | BlockedOrder, ...]`

**Design notes — read this whole block before writing code:**

The loss function, straight from spec §8:

    L(q) = q*(P - S) + entry_commission + exit_commission

with `entry_commission = constraints.commission_per_trade` and
`exit_commission = constraints.commission_per_trade + usd_ceil(sell_fee_rate * q * S)`.
The proportional sell fee (DECA's SEC fee) is estimated at the protective
reference, because that is the price the exit is planned at, and it is rounded
**up** so a rounding error can never make an order look affordable.

Caps, all upper bounds on `q`:
1. **Risk:** largest `q` with `L(q) <= risk_fraction * equity`.
2. **Cash:** `round_shares((spendable_cash - entry_commission) / P)`.
3. **Ceiling:** `round_shares((position_ceiling_fraction * equity - current_position_value) / P)`.

`q = min(caps)`, and `binding_constraint` names the cap that produced the
minimum. Ties break in the order risk → cash → ceiling.

`L` is monotone non-decreasing in `q`, so the risk cap is computed as a
closed-form seed `round_shares((budget - 2*commission) / (P - S))` followed by a
bounded correction loop (`while L(seed + 1) <= budget: seed += 1`, then
`while seed > 0 and L(seed) > budget: seed -= 1`). The loop exists because the
per-share fee is quantized; it converges in a step or two.

**The algorithm never increases risk to reach exactly the risk fraction.** If the
ceiling binds at 200 shares while risk alone would allow 250, the answer is 200
and the planned loss is whatever 200 shares implies. Under-using the risk budget
is correct behavior, not a bug to fix.

Blocks:
- `P < min_price` → `PRICE_BELOW_MINIMUM`.
- `protective_reference is None` or `S >= P` → `INSUFFICIENT_EVIDENCE`, detail naming the problem. A non-positive risk-per-share would make the risk cap unbounded, so there is no safe number to return.
- `q < max(min_shares, 1)` → the reason comes from whichever cap bound: risk → `MIN_LOT_EXCEEDS_RISK`, cash → `MIN_LOT_EXCEEDS_CASH`, ceiling → `POSITION_CEILING`. **Never force the minimum.**

`gap_stress_loss` = `q * P * 0.20 + entry_commission + exit_commission_at_the_gapped_price`. It answers "what if this gaps down 20% through the stop overnight", and it sits beside `planned_risk` because planned risk is not maximum loss and the student must see both.

`size_batch` sorts candidates by `(rank, symbol)` — deterministic, ties on symbol — and reserves cash sequentially: after each `SizedOrder`, `spendable_cash` drops by `notional + commission`. Equity and the ceiling denominator stay pinned to the original frozen snapshot. Two candidates therefore cannot spend the same dollar.

def test_every_sized_order_satisfies_every_cap(scenario):

        return
    q = result.quantity
    assert isinstance(q, int) and q >= max(con.min_shares, 1)
    assert planned_loss(q, price, stop, con) <= con.risk_fraction * con.equity
    assert D(q) * price + con.commission_per_trade <= con.spendable_cash
    assert D(q) * price <= con.position_ceiling_fraction * con.equity


@settings(max_examples=300)
@given(scenarios())
def test_the_solver_is_maximal_one_more_share_would_breach(scenario):
    price, stop, con = scenario
    result = size_order("AAA", price, stop, con)
    if isinstance(result, BlockedOrder):
        return
    q = result.quantity + 1
    breaches = (
        planned_loss(q, price, stop, con) > con.risk_fraction * con.equity
        or D(q) * price + con.commission_per_trade > con.spendable_cash
        or D(q) * price > con.position_ceiling_fraction * con.equity
    )
    assert breaches

        (r.estimated_notional + r.estimated_commission for r in results if isinstance(r, SizedOrder)),

    a = size_order("AAA", price, stop, con)
    b = size_order("AAA", price, stop, con)
    assert a == b

### Task 8: `risk.py`

**Files:**
- Create: `src/investlab/portfolio/risk.py`
- Test: `tests/portfolio/test_risk.py`

**Interfaces:**
- Consumes: `investlab.money.{usd, ZERO}`; `investlab.contracts.{AccountState, BlockReason, BlockedOrder, SizingConstraints}`.
- Produces:
  - `class DrawdownStage(str, Enum)`: `NORMAL`, `REDUCED`, `HALTED`
  - `class MissingReferencePolicy(str, Enum)`: `STRESS`, `BLOCK`
  - `@dataclass(frozen=True) RiskLimits(reduce_at=D("0.05"), halt_at=D("0.10"), reduced_multiplier=D("0.5"), cash_floor_fraction=D("0"), max_position_weight=D("0.30"), max_sector_weight=D("0.50"), max_aggregate_risk_fraction=D("0.06"), missing_reference_stress=D("0.20"))`
  - `@dataclass(frozen=True) PositionRisk(symbol, quantity, mark, protective_reference, planned_risk, is_stressed, basis)`
  - `@dataclass(frozen=True) OpenRiskReport(positions, total_planned_risk, risk_fraction_of_equity, unreferenced, breached_references, blocks_new_risk)`
  - `@dataclass(frozen=True) ConcentrationBreach(scope, key, weight, limit)`
  - `@dataclass(frozen=True) ConcentrationReport(position_weights, sector_weights, breaches)` with `satisfied: bool`
  - `@dataclass(frozen=True) RiskCheck(name, satisfied, detail)`
  - `@dataclass(frozen=True) RiskEvent(at, from_stage, to_stage, equity, high_water_mark, drawdown_fraction, note)`
  - `@dataclass(frozen=True) DrawdownState(high_water_mark, equity, drawdown_fraction, stage, risk_multiplier, entries_allowed, detail)`
  - `def aggregate_open_risk(state, references, *, limits=RiskLimits(), policy=MissingReferencePolicy.STRESS) -> OpenRiskReport`
  - `def concentration(state, sectors, *, limits=RiskLimits()) -> ConcentrationReport`
  - `def cash_floor_check(state, *, limits=RiskLimits()) -> RiskCheck`
  - `class DrawdownMonitor(high_water_mark, *, limits=RiskLimits())` with `observe(equity, as_of) -> DrawdownState`, `record_review(as_of, note) -> DrawdownState`, `state -> DrawdownState`, `events -> tuple[RiskEvent, ...]`, `throttle(constraints) -> SizingConstraints`, `gate_new_entry(symbol) -> BlockedOrder | None`

**Design notes:**
- **Missing risk reference is never zero risk.** Under `STRESS`, an unreferenced position contributes `qty * mark * missing_reference_stress` (20%) with `is_stressed=True` and `basis="20% stress: no protective reference"`. Under `BLOCK`, the report sets `blocks_new_risk=True`. Either way the symbol appears in `unreferenced`. Silence is the one unacceptable answer.
- A reference at or above the mark means the position is already through its stop: risk clamps to zero for the sum but the symbol lands in `breached_references` so it shows up as something to act on.
- **Two-stage drawdown policy.** `drawdown = (hwm - equity) / hwm`. At `>= 5%` the stage becomes `REDUCED` and new-trade risk is halved. At `>= 10%` it becomes `HALTED`: no new entries until a review is recorded.
- **Resumption is explicit.** `observe` never lifts a `HALTED` stage, no matter how far equity recovers. Only `record_review(as_of, note)` does, and it requires a non-empty **student-authored** note — the module never writes one — and appends a `RiskEvent`. `REDUCED` may clear on recovery, but that de-escalation is also appended as a `RiskEvent`, so no transition is ever invisible.
- The high-water mark ratchets up on `observe` and never down.
- `throttle` returns a new `SizingConstraints` with `risk_fraction` multiplied by the stage multiplier (0 when halted, which makes the solver block on `MIN_LOT_EXCEEDS_RISK`). `gate_new_entry` returns a `BlockedOrder(RULE_CONFLICT, ...)` while halted, else `None` — `BlockReason` has no risk-halt member, which is a contract gap to report.

### Task 9: `journal.py`

**Files:**
- Create: `src/investlab/journal.py`
- Test: `tests/test_journal.py`

**Interfaces:**
- Consumes: `investlab.money.usd`; `investlab.contracts.{Action, SizedOrder}`; stdlib `json`, `hashlib`, `datetime`, `pathlib`.
- Produces:
  - `TOOL_NAME = "investlab"`, `def tool_version() -> str`
  - `class EntryKind(str, Enum)`: `DECISION`, `CORRECTION`, `REVIEW`
  - `class EmptyReasoningError(ValueError)`
  - `@dataclass(frozen=True) DecisionFacts(session, symbol, action, quantity, price, indicators, binding_constraints, data_source, note_fields)`
  - `def facts_from_order(order: SizedOrder, session, indicators, data_source) -> DecisionFacts`
  - `@dataclass(frozen=True) JournalEntry(entry_id, kind, recorded_at, facts, reasoning, author, corrects, tool_name, tool_version, prev_hash, entry_hash)`
  - `class Journal(path: Path)` with `record(facts, reasoning, *, author="student", kind=EntryKind.DECISION, recorded_at=None) -> JournalEntry`, `amend(entry_id, reasoning, *, author="student", recorded_at=None) -> JournalEntry`, `entries() -> tuple[JournalEntry, ...]`, `verify_chain() -> bool`
  - `def export_evidence_packet(entries, *, data_sources, generated_at) -> str`

**Design notes — the AI-authorship constraint is the design here:**

Wharton: "You may not submit any work generated by an AI program as your own."
Every trade needs a Trading Note that Wharton audits, and the deliverable
instructions warn: "You must use actual trading notes from trades you made on
WInS. (Yes, we will verify this.)"

So this module has exactly one job with respect to reasoning: **capture it and
store it byte-for-byte.** It supplies the surrounding facts — timestamp, symbol,
action, quantity, price, indicator values at decision time, which constraints
bound, and the data source — and nothing else.

- `record` raises `EmptyReasoningError` when `reasoning.strip()` is empty. There is no default, no placeholder, no template, no suggestion, no autocomplete. Reasoning is stored exactly as passed — not stripped, not normalized, not capitalized.
- **Append-only.** Every write opens the file in `"a"` mode and writes one JSON line. There is no update path and no delete path. A correction is a new `CORRECTION` entry whose `corrects` field carries the original `entry_id`; the original stays in the file forever.
- **Hash chain.** Each entry stores `prev_hash` (the previous entry's `entry_hash`, `""` for the first) and `entry_hash = sha256(canonical_json_without_entry_hash)`. `verify_chain()` re-derives the chain and returns False if any line was edited after the fact. This is what makes "yes, we will verify this" survivable.
- Entry ids are sequential and human-referenceable: `JE-000001`, derived from the line count at write time.
- Decimals serialize as strings and parse back as `Decimal`; dates and datetimes as ISO 8601; `recorded_at` is timezone-aware UTC.
- `export_evidence_packet` emits Markdown: one section per entry with a facts table and the student's reasoning quoted verbatim under a heading that names them as its author, then a provenance footer with tool name, version, data sources, generation timestamp, and an APA-style citation line. **The packet's own words are limited to headings, field labels, and numbers.** It writes no narrative, no summary, no synthesis. If a future requirement asks it to, that requirement stops and gets flagged.
