## Concerns

1. **Two `CompetitionProfile` protocol defects, worked around, not fixed.** `contracts.py` is frozen so these are reported rather than patched:
   - `is_eligible(self, instrument: Instrument, bar: Bar)` takes one bar, but DECA's price rule requires `>= $3.00` on the day before AND the day of. Added `prior_bar: Bar | None = None` as an extra optional third parameter — protocol-compatible (isinstance checks via `runtime_checkable` only look at attribute/method presence, not signatures) but the protocol itself cannot express a two-session rule.
   - `check_rules(self, account: AccountState, today: date)` has no way to receive the sell history needed to compute the one-business-day diversification-restore clock. Added `sell_history: tuple[ClassifiedFill, ...] = ()` as an extra optional third parameter, same compatibility caveat.

2. **A concurrent agent's commit (`63a3eed`, message `"feat(ledger): read-only reconciliation against the platform statement"`) touched `deca.py` and `test_deca.py`.** Diffing it shows the content is byte-for-byte my own in-flight Task 4 edits (the import-block addition and the Task 4 test cases) — nothing from another agent's actual ledger work leaked in, and no content was lost or corrupted. This means another concurrent process ran something like `git commit -am` against the same shared working directory while my edit was mid-flight, capturing my uncommitted changes under its own commit message before I ran my own `git commit`. Net effect is cosmetic (a git-blame/attribution mismatch on part of one commit), not functional — all 44 tests pass against final `HEAD`, and every task's own commit still lands with correct scope for the rest of the sequence. Flagging for the controller since `AGENT-FILE-OWNERSHIP.md`'s "ownership is disjoint at the file level" assumption held for code, but the shared working directory made ownership leak briefly at the git-commit level. No action taken to rewrite history, since amending or rebasing a shared branch mid-flight risks destroying concurrent agents' work.

3. **`ruff check` reports 33 findings, all `FURB157` ("verbose Decimal constructor," e.g. `Decimal("100000")` → `Decimal(100000)`).** Not fixed: the frozen `contracts.py` itself has 6 of the same finding (e.g. `sell_fee_rate: Decimal = Decimal("0")`), confirming this rule isn't an enforced gate in this codebase, and the quoted-string form is the established, more explicit convention for money literals throughout the project (and the safer one — it never risks a float intermediate). Converting to bare-int `Decimal(...)` calls would be a stylistic regression against that convention purely to silence a linter. No other `ruff` findings (no unused imports, no line-length violations).

4. **`MARGIN_MAINTENANCE_FRACTION` (~30%, SECONDARY source only per `deca-verified.md`) is defined but deliberately unenforced** — it's exposed as a constant for future informational use, never used to force a liquidation, consistent with "unverified means unverified."

5. **`position_ceiling` in `check_rules` is always `satisfied=True`.** Holding an appreciated position past the 30% ceiling is compliant under DECA's rules (hold, don't force-sell); the check exists only to report which symbols are at/above the ceiling. The actual buy-blocking enforcement is `can_add_to()`, called separately by the sizing/order path.
