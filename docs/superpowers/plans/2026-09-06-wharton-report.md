## Concerns

1. **Renamed `IPS_DUE` to `INVESTMENT_POLICY_STATEMENT_DUE`.** The plan's Task 1 interface list names the constant `IPS_DUE = date(2026, 11, 6)`, but the plan's own Task 6 test (`test_module_emits_no_submittable_prose`) bans any public module-level name containing the substring `"ips"` — and `"ips_due"` contains it. No test binds to the literal name `IPS_DUE`, so I kept the semantics and picked a name outside the banned-substring set, with a comment at the definition explaining why. Flagging since this is a self-conflict inside the plan itself, not something I resolved unilaterally.

2. **Treasury bonds are accepted without an approved-list check.** `docs/rules/wharton-verified.md` says bonds also come from an approved list ("optional"), but `WhartonSeasonConfig`'s five keys (per the plan's Task 3 interface) carry no bond-list field. `evaluate()` currently lets a `AssetClass.BOND` instrument through to the price-floor check with a code comment noting the gap. Not a `contracts.py` defect — a scope decision baked into the plan's own config schema. If a future config revision adds an approved bond list, `evaluate()` has an explicit comment marking where to wire it in.

3. **`ruff check` reports 44 `FURB157` findings** ("verbose Decimal constructor", e.g. `Decimal("500000")` → `Decimal(500000)`). Not fixed: the frozen `src/investlab/contracts.py` itself triggers 6 of the same finding under this ruff version's default rule set (confirmed by running `ruff check` against it directly), so the quoted-string form is this codebase's established, safer convention for money literals. `ruff check --ignore FURB157` is clean; `ruff format --check` is clean.

4. **No `CompetitionProfile` protocol defects found**, unlike DECA's module. `is_eligible(instrument, bar)` and `check_rules(account, today)` cover Wharton's single-session rules without needing extra parameters — Wharton has no two-session price rule or sell-history-dependent clock analogous to DECA's diversification-restore window.

5. **`minimum_trading_activity` is `satisfied=False` from day one of a verified season**, even well before its deadline, as long as zero trades have been recorded (`TradeBudget.trades_used == 0`). This is deliberate and matches the plan's own test (`test_minimum_trading_activity_deadline_is_reported_with_its_date` expects `satisfied is False` on 2026-10-01 against an 2026-10-09 deadline with an empty budget) — the check reports "have you traded yet," not "is the deadline still open." Its `deadline` field carries the actual date so a caller can distinguish urgency.

6. **No submittable prose is generated anywhere in the module** (verified by `test_module_emits_no_submittable_prose`, which scans every public module-level name for banned fragments). `WhartonSeasonConfig.client_mandate_summary` is stored and echoed verbatim from student input, never generated or edited. All `RuleCheck`/`BlockedOrder` detail strings are template-filled facts and numbers, not narrative.
