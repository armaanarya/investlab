## Contract reading that drives the design

`DailyPlan.is_actionable` is:

```python
return not self.data_is_stale and all(
    c.satisfied for c in self.rule_checks if c.status is RuleStatus.VERIFIED
)
```

Only checks with status `VERIFIED` can make a plan non-actionable. An `INCOMPLETE` check is invisible to `is_actionable`. Therefore the UNVERIFIED state needs BOTH:

1. an `INCOMPLETE` check that names 2026-09-15 and enumerates what is missing (the requirement), and
2. a `VERIFIED`, `satisfied=False` check that actually closes the gate (the mechanism).

That is defensible semantically: `RuleStatus` describes confidence in the *rule*, and "do not trade under rules you have not read, which arrive 2026-09-15" is a confirmed rule. `INCOMPLETE` describes our knowledge of the *season parameters*. Both checks ship, and the split is documented in the module.

Second consequence: a *warning* must never be `VERIFIED` + `satisfied=False`, or it would silently kill the order sheet. Warnings are `satisfied=True` with escalation carried in `detail` and in a separate machine-readable `BudgetSeverity`. Only a hard block (200-trade cap, margin/short violation) is `VERIFIED` + `satisfied=False`.
